# Internationalization

FinteraUI ships with English (`en`) and Spanish (`es`) translations.

## How it works

- `src/contexts/LocaleContext.jsx` loads `src/locales/en.json` and
  `src/locales/es.json`.
- The default locale is `es`; the fallback locale is `en`.
- The selected locale is persisted in `localStorage` under `userLocale`.
- `useLocale()` exposes:
  - `locale` and `setLocale(locale)`
  - `t(key, params)` for nested keys and `{param}` interpolation
  - `getSupportedLocales()` and `getCurrentLocaleName()`

## Usage

```jsx
import { useLocale } from "@/contexts/LocaleContext";

function Example() {
  const { t } = useLocale();
  return <button>{t("common.save")}</button>;
}
```

Nested keys use dot notation. Interpolation replaces `{name}` placeholders:

```jsx
t("users.greeting", { name: user.name });
```

## Adding strings

1. Add the key to **both** `src/locales/en.json` and `src/locales/es.json`.
2. Reuse existing keys under `common.*` when possible.
3. Prefer `t(...)` over hard-coded user-facing text in new components.
4. If a string is intentionally not localized, explain why in the change.

Missing keys fall back to English and then to the key itself, so a missing
translation is visible rather than crashing the UI.

## Conventions

- Keep keys grouped by feature or domain (`contracts.*`, `payments.*`,
  `users.*`).
- Do not rename existing keys without updating all call sites.
- See `.agents/rules/internationalization.md` for the agent rule.
