# User documentation (in-app guide)

The in-app User Guide at `/docs` explains the system's terms and operating logic
to staff. It is **read-only** content bundled with the app; there is no backend
or database dependency.

## Who can see it

- **Admins** see every article.
- **Sellers** see only articles tagged for sellers (viewing projects/lots,
  reservations, payments, reports, glossary). Admin-only operations — approvals,
  project/lot management, settings, branding — are hidden. Shared articles can
  provide a seller-specific version; the overview article uses this to show only
  the operations a seller can perform.
- **Regular users** are sent to the forbidden page; the guide is not shown in
  the sidebar. Admins and sellers both reach it from the **Guide** entry.

Access uses `AdminOrOwnerRoute` on both `/docs` and `/docs/:slug`.

## Code layout

```
src/features/docs/
  data/manifest.js          # sections, articles, per-locale titles, audience
  content/
    index.js                # Vite import.meta.glob loader with role variants
    en/<section>/<slug>.md  # English articles
    es/<section>/<slug>.md  # Spanish articles
    <locale>/<section>/<slug>.<role>.md  # optional role-specific variant
  hooks/
    useDocs.js              # locale + role filtering
    useDocsSearch.js        # fuse.js search
  components/
    DocsSidebar.jsx         # sections, article links, search
    DocsSearch.jsx          # search input
    MarkdownViewer.jsx      # react-markdown + remark-gfm + rehype-slug
    TableOfContents.jsx     # reads rendered h2/h3 ids
  pages/index.jsx           # two-column guide layout
```

## Adding or editing an article

1. Add an entry to `ARTICLES` in `src/features/docs/data/manifest.js` with a
   unique `slug`, `section`, `order`, `audience`, and `en`/`es` titles.
2. Add the matching markdown file under `content/en/<section>/<slug>.md` and
   `content/es/<section>/<slug>.md`.
3. Optional: add `content/<locale>/<section>/<slug>.<role>.md` (for example
   `overview-and-roles.seller.md`) to replace the body for one role. The loader
   falls back to the shared article and then to English.
4. Markdown supports GitHub-flavored tables, lists, and headings. Heading ids are
   generated by `rehype-slug` and drive the article table of contents.
5. Internal links use `/docs/<slug>` so they navigate through React Router.

`audience` controls visibility: `["admin", "seller"]` for shared articles,
`["admin"]` for admin-only operations. Role variants only change the body, not
the article's slug, title, or audience.

## Content conventions

- Write for operators, not developers: define the term, explain the rule, then
  give a numeric example.
- Keep terminology aligned with the UI locale files (`src/locales/en.json`,
  `src/locales/es.json`).
- The overdue-interest article documents the exact formula:
  `installment × (days overdue ÷ 365) × (project rate ÷ 100)`, only for
  installments on approved active contracts, and no charge when the project rate
  is zero.
