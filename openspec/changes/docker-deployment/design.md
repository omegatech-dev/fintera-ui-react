## Context

See `proposal.md`. The app is a static SPA build (`dist/`) generated by Vite;
`vite-plugin-pwa` emits `sw.js`, `workbox-*.js`, and `manifest.webmanifest`.
The current runtime uses the `serve` npm package via `npm start`. Node 26 is the
project baseline.

## Goals / Non-Goals

**Goals:**

- Small production image with no Node runtime in the final stage.
- Correct SPA deep-link fallback and PWA cache headers.
- Runtime port driven by `PORT`, with a sensible default.
- Reproducible local and Railway builds from the committed lockfile.

**Non-Goals:**

- Proxying API requests inside the container (the SPA calls `VITE_API_URL`).
- Adding TLS termination or a reverse proxy (handled by the platform).
- Replacing the Heroku `Procfile`/`serve` path.

## Decisions

### Multi-stage Node build + Nginx runtime

Building in `node:26-alpine` keeps the build identical to CI and local output.
The final stage uses `nginx:alpine` (~50 MB) instead of shipping Node and
`node_modules`, which keeps image size and startup time low. Nginx also gives
direct control over cache headers and SPA fallback.

Alternative: keep `serve` in a Node runtime. Rejected because it keeps a full
Node image and offers less control over headers/fallback for the PWA.

### `PORT` via nginx template

The official Nginx image expands `${PORT}` in files copied to
`/etc/nginx/templates` at startup. `ENV PORT=8080` provides a local default and
Railway overrides it. No entrypoint wrapper is needed.

### Build args for `VITE_*`

Vite bakes `VITE_*` values into the bundle. The Dockerfile declares build args
for `VITE_API_URL`, `VITE_APP_ENV`, `VITE_ROLLBAR_ACCESS_TOKEN`, and
`VITE_APP_VERSION`; runtime environment variables cannot change them.

### Cache policy

`index.html`, `sw.js`, and `manifest.webmanifest` are served with `no-cache` so
new deploys are picked up; hashed files under `/assets` get a one-year immutable
cache. Missing assets return 404 instead of falling back to `index.html`.

## Risks / Trade-offs

- **Stale `VITE_API_URL`** → Documented as a build arg; changing it requires a
  rebuild, which Railway does on each deploy.
- **Service worker caching an old bundle** → `sw.js` is always revalidated and
  `registerType: "autoUpdate"` updates clients.
- **`${PORT}` unset at container start** → `ENV PORT=8080` guarantees a value.
- **Nginx template envsubst touching `$uri`** → The official entrypoint only
  substitutes variables defined in the environment; `uri` is not one, so nginx
  directives remain intact.
- **Missing health endpoint** → The Dockerfile healthcheck requests `/`, which
  is served by the SPA.
